02

Cos'è un LLMWhat is an LLM

Una frase per iniziare, poi scava finché ti serve. Ogni strato aggiunge un livello di dettaglio.

One sentence to start, then dig as deep as you need. Each layer adds a level of detail.

SuperficieSurface LV 1

Un LLM è un programma che, dato un testo, prevede il pezzo di testo successivo. Ripetuto migliaia di volte, quel singolo trucco produce codice, spiegazioni e piani. Non "sa" cose come un database: ha imparato schemi statistici da enormi quantità di testo e codice.

An LLM is a program that, given some text, predicts the next piece of text. Repeated thousands of times, that single trick produces code, explanations and plans. It doesn't "know" things like a database does: it has learned statistical patterns from huge amounts of text and code.

Prossimo tokenNext token LV 2

A ogni passo il modello produce una distribuzione di probabilità su tutti i token possibili, poi ne sceglie uno (sampling). La temperature decide quanto osare: bassa = scelte prevedibili, alta = più varietà e più errori. Provalo qui sotto.

At every step the model produces a probability distribution over all possible tokens, then picks one (sampling). Temperature decides how bold to be: low = predictable choices, high = more variety and more mistakes. Try it below.

Dentro il modelloInside the model LV 3

  • Token → embedding: ogni token diventa un vettore di migliaia di numeri che ne cattura il "significato".
  • Transformer: decine di strati che rielaborano quei vettori. Il pezzo chiave è l'attention: ogni token "guarda" tutti i precedenti e decide quali contano. È per questo che il contesto conta così tanto.
  • Pesi (weights): miliardi di parametri numerici. Sono il modello. "Open weight" significa che puoi scaricare proprio questi.
  • Il costo dell'attention cresce con la lunghezza del contesto: più contesto = più lento, più caro, e più facile che l'informazione importante si perda in mezzo.
  • Token → embedding: each token becomes a vector of thousands of numbers that captures its "meaning".
  • Transformer: dozens of layers that rework those vectors. The key piece is attention: each token "looks at" all the previous ones and decides which matter. That's why context matters so much.
  • Weights: billions of numeric parameters. They are the model. "Open weight" means you can download exactly these.
  • Attention cost grows with context length: more context = slower, more expensive, and more likely that important information gets lost in the middle.

Come nasceHow it's made LV 4

  • Pre-training: prevedere il token successivo su trilioni di token. Ne esce un "completatore" bravissimo ma non un assistente.
  • Fine-tuning su istruzioni: esempi di domanda e risposta lo trasformano in assistente.
  • RL da feedback (umano o automatico, es. test che passano): lo allinea a cosa è utile, sicuro, corretto. Qui nascono le capacità agentiche e di uso dei tool.
  • Knowledge cutoff: dopo una certa data il modello non sa nulla. Le API e le librerie nuove vanno date nel contesto.
  • Pre-training: predicting the next token over trillions of tokens. The result is an excellent "autocompleter", not an assistant.
  • Instruction fine-tuning: question and answer examples turn it into an assistant.
  • RL from feedback (human or automatic, e.g. passing tests): aligns it with what is useful, safe and correct. This is where agentic and tool-use skills come from.
  • Knowledge cutoff: after a certain date the model knows nothing. New APIs and libraries must be provided in context.

Limiti da veteranoVeteran-level limits LV 5

  • Allucinazioni: il modello genera ciò che è plausibile, non ciò che è vero. Un metodo inesistente "suona" giusto quanto uno reale. Antidoto: test, compilatore, tool che verificano.
  • Non determinismo: stesso prompt, risposte diverse. Progetta il workflow perché sia verificabile, non ripetibile.
  • Reasoning / thinking: alcuni modelli "ragionano" generando token intermedi prima della risposta. Più qualità sui problemi difficili, più token pagati.
  • Context rot: oltre una certa soglia di riempimento la qualità cala, anche se tecnicamente "ci sta".
  • Hallucinations: the model generates what is plausible, not what is true. A non-existent method "sounds" as right as a real one. Antidote: tests, the compiler, tools that verify.
  • Non-determinism: same prompt, different answers. Design the workflow to be verifiable, not repeatable.
  • Reasoning / thinking: some models "reason" by generating intermediate tokens before answering. Better quality on hard problems, more tokens paid.
  • Context rot: past a certain fill level quality drops, even if it technically "fits".
PROFONDITÀDEPTH

Do BUFF

  • Tratta l'output come la PR di un collega bravo ma distratto: si rivede sempre.
  • Chiudi il cerchio con verifiche automatiche: compilazione, test, linter.
  • Dai al modello la documentazione delle librerie recenti invece di sperare che la conosca.
  • Treat the output like a PR from a skilled but distracted colleague: always review it.
  • Close the loop with automatic checks: compilation, tests, linters.
  • Give the model the docs of recent libraries instead of hoping it knows them.

Don't DEBUFF

  • Chiedere "sei sicuro?" come verifica: risponde in modo plausibile, non controlla.
  • Usare un LLM per calcoli esatti o dati che cambiano senza un tool.
  • Antropomorfizzare: "ha capito" e "si ricorda" sono scorciatoie, non fatti.
  • Asking "are you sure?" as verification: it answers plausibly, it doesn't check.
  • Using an LLM for exact calculations or changing data without a tool.
  • Anthropomorphising: "it understood" and "it remembers" are shortcuts, not facts.

Token e context windowTokens and context window

I modelli non leggono caratteri né parole: leggono token. Tutto si misura e si paga in token, e tutto deve stare nella finestra di contesto.

Models don't read characters or words: they read tokens. Everything is measured and paid in tokens, and everything must fit in the context window.

Regole di massimaRules of thumb

  • Inglese: circa 4 caratteri per token. Italiano e codice ne usano di più a parità di significato.
  • Paghi input (tutto ciò che mandi, a ogni turno) e output (tipicamente 3-5 volte più caro per token).
  • Il prompt caching rende molto più economico l'input ripetuto identico: prefissi stabili (system prompt, AGENTS.md) prima, parti variabili dopo.
  • Ogni turno di un agente rimanda tutta la conversazione. Un log da 20k token letto al turno 3 lo ripaghi a ogni turno successivo.
  • English: about 4 characters per token. Italian and code use more tokens for the same meaning.
  • You pay for input (everything you send, every turn) and output (typically 3-5 times more expensive per token).
  • Prompt caching makes identical repeated input much cheaper: stable prefixes (system prompt, AGENTS.md) first, variable parts after.
  • Every agent turn resends the whole conversation. A 20k-token log read at turn 3 is paid again on every following turn.

04

Open vs closed weight

La domanda non è "quale è migliore" ma chi tiene i pesi, e quindi chi paga cosa.

The question isn't "which is better" but who holds the weights, and therefore who pays for what.

Closed weight

I pesi restano al provider. Usi il modello solo via API o prodotto (Claude, GPT, Gemini).

Cosa paghi: per token, input e output separati, con sconti per cache e batch. Oppure abbonamento a posto utente.

Ottieni: i modelli più capaci, zero infrastruttura, aggiornamenti continui.

Rischi: dati che escono dal perimetro, modello che cambia o viene ritirato, costi variabili con l'uso, lock-in.

The weights stay with the provider. You use the model only via API or product (Claude, GPT, Gemini).

What you pay: per token, input and output priced separately, with discounts for caching and batch. Or a per-seat subscription.

You get: the most capable models, zero infrastructure, continuous updates.

Risks: data leaving your perimeter, models that change or get retired, usage-driven costs, lock-in.

Open weight

I pesi sono scaricabili (Llama, Qwen, Mistral, DeepSeek, gpt-oss). Li fai girare dove vuoi.

Cosa paghi: hardware (GPU, RAM), energia, operazioni. Oppure un host che lo serve per te, di nuovo a token, di solito meno caro.

Ottieni: controllo, privacy, costo prevedibile, versione congelata, fine-tuning possibile.

Rischi: qualità inferiore sui compiti agentici lunghi, licenze con clausole d'uso, il lavoro di gestione è tuo.

The weights are downloadable (Llama, Qwen, Mistral, DeepSeek, gpt-oss). You run them wherever you want.

What you pay: hardware (GPU, RAM), energy, operations. Or a host that serves it for you, again per token, usually cheaper.

You get: control, privacy, predictable cost, a frozen version, fine-tuning is possible.

Risks: lower quality on long agentic tasks, licences with usage clauses, the operations work is yours.

Trappola classica: open weight non è open sourceClassic trap: open weight is not open source

Hai i pesi, ma quasi mai i dati di training né il codice per riprodurli. E la licenza può limitare l'uso commerciale o imporre condizioni. Leggila prima di metterlo in produzione.

You get the weights, but almost never the training data or the code to reproduce them. And the licence may restrict commercial use or impose conditions. Read it before going to production.

Do BUFF

  • Scegli per compito: closed per agenti lunghi e refactoring, open per classificazione, estrazione, dati riservati.
  • Calcola il costo totale: token × volume contro hardware + persone + tempo.
  • Metti entrambi dietro lo stesso gateway, così cambiare modello è una riga di config.
  • Choose per task: closed for long agents and refactoring, open for classification, extraction, confidential data.
  • Compute the total cost: tokens × volume versus hardware + people + time.
  • Put both behind the same gateway, so switching model is one line of config.

Don't DEBUFF

  • Scegliere un modello open "per risparmiare" senza misurare la qualità sul tuo caso.
  • Ignorare la licenza perché "è su Hugging Face".
  • Dare per scontato che "closed" significhi che i tuoi dati vengono usati per il training: verifica il contratto, spesso non è così via API.
  • Choosing an open model "to save money" without measuring quality on your use case.
  • Ignoring the licence because "it's on Hugging Face".
  • Assuming "closed" means your data is used for training: check the contract, via API it often isn't.
